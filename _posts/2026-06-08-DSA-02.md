Chào các bạn, trong bài trước ta đã hiểu array lưu trữ liên tiếp trong RAM và truy cập index có độ phức tạp O(1). Hôm nay chúng ta sẽ phân biệt **Static Array** và **Dynamic Array** — hai biến thể quan trọng nhất của array trong thực tế.

## 1. Static Array:

**Static Array** có kích thước **cố định** khi khai báo. Ví dụ trong C:

```c
int arr[5] = {1, 2, 3, 4, 5};  // không thể thêm phần tử thứ 6
```

+ Kích thước xác định tại compile-time (hoặc khi cấp phát)
+ Bộ nhớ được cấp phát trên **stack** (local) hoặc **heap** (malloc)
+ Không thể mở rộng sau khi tạo
+ Phù hợp khi biết trước số lượng phần tử

## 2. Dynamic Array:

**Dynamic Array** (như Python `list`, Java `ArrayList`, C++ `vector`) tự động **resize** khi cần thêm phần tử. Bên trong gồm hai khái niệm:

+ **size**: số phần tử hiện có
+ **capacity**: số ô bộ nhớ đã cấp phát

Khi `size == capacity`, dynamic array thực hiện **resize**:
1. Cấp phát mảng mới với capacity lớn hơn (thường gấp đôi)
2. Copy toàn bộ phần tử cũ sang mảng mới
3. Giải phóng mảng cũ

> **Lưu ý**: Một lần append có thể tốn O(n) do resize, nhưng **amortized analysis** cho thấy trung bình mỗi append vẫn là **O(1)** — vì resize xảy ra hiếm (khi capacity gấp đôi).

## 3. So sánh thao tác:

| Thao tác | Static Array | Dynamic Array |
|----------|-------------|---------------|
| Access `arr[i]` | O(1) | O(1) |
| Append cuối | N/A (full) | O(1) amortized |
| Insert giữa | O(n) | O(n) |
| Delete giữa | O(n) | O(n) |
| Search (unsorted) | O(n) | O(n) |

## Common Mistakes: Static vs Dynamic Array

- **Amortized O(1) ≠ O(1) worst case**: Một lần append khi resize vẫn tốn O(n). Đừng dùng dynamic array khi cần guaranteed O(1) mỗi operation (real-time systems).
- **Capacity ≠ Size**: `len(list)` trong Python là size, không phải capacity. Capacity là implementation detail.
- **Copy-on-write**: Một số ngôn ngữ (Swift Array) dùng COW — thay đổi có thể trigger copy ngay cả khi chưa full capacity.
