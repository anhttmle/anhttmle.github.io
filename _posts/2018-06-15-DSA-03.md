Chào các bạn, sau khi hiểu array và cách nó hoạt động trong bộ nhớ, hôm nay chúng ta sẽ học cách **đo lường hiệu suất** giải thuật bằng **Big O Notation** — ngôn ngữ chung để so sánh độ phức tạp thuật toán.

## 1. Tại sao cần Big O?

Khi đánh giá giải thuật, ta quan tâm cách thời gian chạy và bộ nhớ **tăng theo kích thước input** \\(n\\), không phải thời gian tuyệt đối (phụ thuộc CPU, ngôn ngữ lập trình).

**Big O** mô tả **upper bound** (cận trên) — trường hợp xấu nhất hoặc asymptotic behavior khi \\(n \to \infty\\).

## 2. Các mức độ phổ biến:

| Big O | Tên | Ví dụ |
|-------|-----|-------|
| O(1) | Constant | Truy cập `arr[i]`, hash lookup |
| O(log n) | Logarithmic | Binary search |
| O(n) | Linear | Duyệt array một lần |
| O(n log n) | Linearithmic | Merge sort, heap sort |
| O(n²) | Quadratic | Nested loop, bubble sort |
| O(2ⁿ) | Exponential | Naive recursion Fibonacci |

## 3. Quy tắc tính Big O:

+ **Bỏ hằng số**: O(2n) → O(n), O(500) → O(1)
+ **Chỉ giữ term lớn nhất**: O(n² + n) → O(n²)
+ **Nested loop nhân complexity**: 2 vòng lặp n → O(n²)
+ **Sequential operations cộng, lấy max**: O(n) + O(n²) → O(n²)

> **Lưu ý**: Big O mô tả **time complexity**. **Space complexity** đo bộ nhớ phụ thêm (không tính input). Ví dụ: merge sort O(n) space, quick sort O(log n) space (recursion stack).

## 4. Time vs Space trade-off:

Nhiều giải thuật đánh đổi thời gian lấy bộ nhớ (hoặc ngược lại). **Hash Map** dùng O(n) space để đạt O(1) lookup — ta sẽ học ở Part 5.

## Common Mistakes: Big O

- **Best case ≠ Big O**: Big O thường chỉ worst/average case. Quick sort worst O(n²) dù average O(n log n).
- **O(2n) không phải exponential**: O(2n) = O(n). Exponential là O(2ⁿ).
- **Quên space complexity**: Recursive DFS tốn O(h) stack space với h = chiều cao tree.
- **Input size definition**: Với matrix n×n, n là một chiều hay tổng n² phần tử? Cần thống nhất khi phân tích.
