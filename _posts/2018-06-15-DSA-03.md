Chào các bạn, giả sử bạn viết hai cách giải bài "tìm số lớn nhất trong danh sách": cách A duyệt một lần, cách B so sánh từng cặp. Cả hai đều đúng — nhưng cái nào **scale** tốt hơn khi danh sách tăng từ 100 lên 1 triệu phần tử? **Big O Notation** giúp ta trả lời câu hỏi đó mà không cần chạy benchmark trên mọi máy.

## 1. Intuition

Hãy nghĩ về **tìm một cuốn sách** trong thư viện:

+ **O(1)**: Biết chính xác kệ số 42 → đi thẳng tới (1 bước, không phụ thuộc số sách trong thư viện)
+ **O(n)**: Không biết kệ → duyệt từng kệ một (worst case: duyệt hết n kệ)
+ **O(log n)**: Sách xếp theo mã, tra catalog rồi **chia đôi** khu vực tìm kiếm mỗi bước
+ **O(n²)**: So sánh **từng cặp** sách với nhau (nested loop)

Big O mô tả **cách thời gian tăng** khi input lớn dần — không phải thời gian chạy tuyệt đối (giây).

## 2. Cách đọc Big O — từng mức

| Big O | Tên | Ví dụ | Khi n=1000 |
|-------|-----|-------|------------|
| O(1) | Constant | `arr[i]`, hash lookup | ~1 bước |
| O(log n) | Logarithmic | Binary search | ~10 bước |
| O(n) | Linear | Duyệt array 1 lần | ~1000 bước |
| O(n log n) | Linearithmic | Merge sort | ~10000 bước |
| O(n²) | Quadratic | Nested loop n×n | ~1,000,000 bước |
| O(2ⁿ) | Exponential | Naive Fibonacci | Rất lớn |

**Trace through nested loop O(n²):**

```python
for i in range(n):      # chạy n lần
    for j in range(n):  # mỗi lần i, chạy thêm n lần
        print(i, j)
```

Tổng số lần in = n × n = n² → **O(n²)**.

## 3. Tại sao Big O bỏ hằng số?

Big O mô tả **xu hướng tăng trưởng** khi n → ∞, không phải hằng số nhỏ.

+ O(2n) và O(n) **cùng growth rate** → viết O(n)
+ O(500) → O(1) vì 500 không đổi khi n tăng
+ O(n² + n) → O(n²) vì n² chiếm ưu thế khi n lớn

**Ví dụ số:** n = 1,000,000
+ O(n): ~1,000,000 bước
+ O(n²): ~1,000,000,000,000 bước — chênh **1 triệu lần**

## 4. Quy tắc tính nhanh

1. **Vòng lặp tuần tự** → cộng, lấy max: O(n) + O(n²) = O(n²)
2. **Vòng lặp lồng nhau** → nhân: O(n) × O(n) = O(n²)
3. **Chia đôi mỗi bước** → O(log n)
4. **Space complexity**: đếm bộ nhớ **phụ** thêm (không tính input)

> **Lưu ý**: Big O thường chỉ **worst case** hoặc **average case**. Quick sort average O(n log n) nhưng worst O(n²).

## Common Mistakes: Big O

- **Best case ≠ Big O**: Big O thường là worst/average. Đừng dùng best case làm đại diện.
- **O(2n) = O(n)**, không phải exponential. Exponential là O(2ⁿ).
- **Quên space complexity**: Recursive DFS tốn O(h) stack với h = chiều cao tree.
- **Input size**: Matrix n×n — n là một chiều; số ô là n². Cần thống nhất khi phân tích.
