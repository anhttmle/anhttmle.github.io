Chào các bạn, ở bài trước ta đã hiểu Hash Map và Hash Set ở mức khái niệm. Hôm nay ta đi sâu vào **implementation** — cách xử lý **collision** và các **pattern sử dụng** hash trong bài toán thực tế.

## 1. Collision — va chạm hash:

Hai key khác nhau có thể map cùng bucket index → **collision**. Có hai cách xử lý chính:

+ **Chaining**: Mỗi bucket là linked list (hoặc dynamic array nhỏ) chứa các entry collision
+ **Open Addressing**: Tìm slot trống tiếp theo trong cùng array (linear probing, quadratic probing)

## 2. Load Factor & Rehashing:

**Load factor** = số entry / số bucket. Khi load factor vượt ngưỡng (thường 0.75), hash table **rehash** — tạo bảng lớn hơn (thường gấp đôi) và re-insert tất cả entries.

Average case vẫn O(1) nhờ load factor được kiểm soát.

## 3. Hash Usage Patterns:

+ **Frequency count**: `map[key] += 1` — đếm tần suất ký tự/từ
+ **Complement lookup**: Two Sum — tìm `target - current` trong map
+ **Grouping**: Group Anagrams — key = sorted string hoặc char count tuple
+ **Visited set**: BFS/DFS trên graph — O(1) check đã thăm

## 4. Hash Set vs Hash Map — khi nào dùng?

| Cần | Dùng |
|-----|------|
| Chỉ check tồn tại / uniqueness | Hash Set |
| Lưu thêm metadata (index, count) | Hash Map |
| Đếm frequency | Hash Map (key → count) |

## Common Mistakes: Hash Implementation

- **Không xử lý collision**: Custom hash table phải implement chaining hoặc probing.
- **Bad hash function**: Keys cùng pattern (vd: "a1", "b1", "c1") → nhiều collision nếu hash đơn giản.
- **Quên rehash**: Load factor cao → chains dài → O(n) lookup.
- **Dùng hash khi cần order**: Hash Map không giữ thứ tự (trừ OrderedDict / LinkedHashMap).
