Chào các bạn, bạn có 1000 học sinh và cần tìm "Nguyễn Văn A" trong danh sách. Cách chậm: đọc từng tên. Cách nhanh: dùng **sổ tra cứu** — biết tên, lật đúng trang, có ngay thông tin. **Hash Map** trong máy tính hoạt động giống cuốn sổ tra cứu đó.

## 1. Intuition

**Hash Map** = từ điển: tra **từ khóa (key)** → nhận **nghĩa (value)**.
+ Key "apple" → value "táo"
+ Key "name" → value "Alice"

**Hash Set** = danh sách "đã có mặt" tại buổi họp: chỉ quan tâm **có hay chưa**, không cần value.

## 2. Hash Map — cách hoạt động từng bước

Bên trong là một **array of buckets**. Hash function biến key thành index:

\\[
\text{index} = \text{hash}(\text{key}) \mod \text{table\_size}
\\]

**Trace through insert và lookup:**

1. `put("name", "Alice")`: hash("name") → bucket 2 → lưu ("name", "Alice")
2. `put("age", 25)`: hash("age") → bucket 5 → lưu ("age", 25)
3. `get("name")`: hash("name") → bucket 2 → trả "Alice" — **không duyệt toàn bộ map**

| Thao tác | Average | Worst (nhiều collision) |
|----------|---------|-------------------------|
| get / put / remove | O(1) | O(n) |

> **Lưu ý**: Key phải **immutable** (int, str, tuple). List không làm key được vì hash thay đổi khi list thay đổi.

## 3. Hash Set — khi nào dùng?

Chỉ cần kiểm tra **tồn tại** hoặc **không trùng lặp**:
+ "Số này đã xuất hiện chưa?"
+ "Có phần tử trùng trong array không?"

Không cần lưu thêm metadata → Hash Set gọn hơn Hash Map.

## 4. Tại sao Two Sum dùng Hash Map?

**Bài toán:** Tìm hai số trong array có tổng = target.

**Cách chậm O(n²):** Mỗi cặp (i, j) kiểm tra `nums[i] + nums[j] == target`.

**Cách nhanh O(n):** Duyệt từng `nums[i]`, cần tìm `complement = target - nums[i]`. Hỏi Hash Map: *"complement đã gặp chưa?"*

**Invariant:** Hash Map lưu các giá trị đã duyệt → `{value: index}`.

**Tại sao đúng?** Nếu tồn tại cặp (a, b) với a + b = target, khi duyệt tới phần tử thứ hai (b), complement (a) đã nằm trong map (vì a được duyệt trước).

## 5. Phân tích độ phức tạp

+ Hash Map insert/lookup/delete: **O(1) average**
+ Two Sum với Hash Map: **O(n) time**, **O(n) space**

## Common Mistakes: Hash Map & Hash Set

- **Worst case O(n)**: Nhiều key collision vào cùng bucket → chain dài.
- **Mutable key**: Không dùng list/dict làm key trong Python.
- **Hash Set vs Sort**: Cần check tồn tại O(1) → Set. Cần thứ tự sorted → sort O(n log n).
