Chào các bạn, ở bài trước ta biết array lưu liên tiếp trong RAM và truy cập index là O(1). Nhưng khi bạn viết `scores = []` rồi liên tục `append` điểm mới — chuyện gì xảy ra bên trong? Hôm nay ta trả lời câu hỏi đó bằng cách so sánh **Static Array** và **Dynamic Array**.

## 1. Intuition

Hãy nghĩ về **bãi đậu xe cố định** vs **bãi đậu có thể mở rộng**:

+ **Static array** = bãi có đúng 5 chỗ. Xe thứ 6 đến → không có chỗ, phải từ chối hoặc chuyển sang bãi khác (cấp phát mới).
+ **Dynamic array** = bãi ban đầu 4 chỗ, khi đầy thì xây bãi mới 8 chỗ, chuyển xe sang, phá bãi cũ.

Câu hỏi quan trọng: *"Mở rộng bãi tốn kém — vậy append trung bình có chậm không?"* Ta sẽ chứng minh câu trả lời là **không** (amortized O(1)).

## 2. Static Array — cách hoạt động

**Static array** có kích thước **cố định** khi tạo:

```c
int arr[5] = {1, 2, 3, 4, 5};  // không thể thêm phần tử thứ 6
```

+ Kích thước xác định lúc compile hoặc lúc `malloc`
+ Bộ nhớ trên **stack** (biến local) hoặc **heap** (`malloc`)
+ **Không resize** — muốn lớn hơn phải cấp phát mảng mới và copy

Phù hợp khi biết trước số phần tử (vd: ma trận 3×3, ngày trong tuần = 7).

## 3. Dynamic Array — từng bước resize

**Dynamic array** (Python `list`, Java `ArrayList`, C++ `vector`) có hai con số:

+ **size**: số phần tử đang dùng
+ **capacity**: số ô bộ nhớ đã cấp phát

**Trace through append khi đầy:**

Giả sử `capacity = 4`, `size = 4`, array = `[1, 2, 3, 4]`. Gọi `append(5)`:

1. `size == capacity` → cần resize
2. Cấp phát mảng mới `capacity = 8`
3. Copy `[1,2,3,4]` sang mảng mới
4. Gán `5` vào index 4
5. Giải phóng mảng cũ
6. `size = 5`

> **Lưu ý**: Một lần append khi resize tốn O(n). Nhưng resize xảy ra hiếm (khi capacity gấp đôi: 4→8→16→32…), nên **trung bình** mỗi append vẫn O(1) — gọi là **amortized O(1)**.

## 4. Tại sao amortized append là O(1)?

**Ý tưởng đếm tổng chi phí:**

Khi append n lần với capacity gấp đôi mỗi lần resize:
+ Resize tại size 1, 2, 4, 8, …, n
+ Tổng chi phí copy ≈ 1 + 2 + 4 + … + n < 2n
+ Trung bình mỗi append: 2n / n = **O(1)**

**Invariant:** Sau mỗi append thành công (không resize), `size ≤ capacity` và phần tử mới nằm tại `arr[size-1]`.

## 5. Phân tích độ phức tạp

| Thao tác | Static | Dynamic |
|----------|--------|---------|
| Access `arr[i]` | O(1) | O(1) |
| Append cuối | N/A nếu full | O(1) amortized, O(n) worst case |
| Insert giữa | O(n) | O(n) |
| Delete giữa | O(n) | O(n) |

## Common Mistakes: Static vs Dynamic Array

- **Amortized O(1) ≠ O(1) mọi lần**: Một lần append khi full vẫn O(n). Hệ thống real-time cần cẩn thận.
- **Capacity ≠ Size**: `len(list)` trong Python là size, không phải capacity.
- **Insert đầu/cuối/giữa**: Chỉ append **cuối** là O(1) amortized. Insert đầu vẫn O(n) vì phải dịch toàn bộ.
