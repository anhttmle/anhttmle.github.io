Thay vì mỗi lần được hỏi “tổng điểm từ tuần 3 đến tuần 7” lại cộng lại từ đầu, bạn ghi **bảng tích lũy** ngay từ đầu kỳ: “đến hết tuần k, tổng là bao nhiêu”. Muốn tổng tuần 3→7? Lấy tích lũy tuần 7 **trừ** tích lũy trước tuần 3. Một phép trừ thay vì cộng lại nhiều số — đó là **1D Prefix Sum**.

## 1. Intuition

+ **Sổ chi tiêu**: Dòng “tổng từ đầu tháng” — range “ngày 5–12” = tổng ngày 12 − tổng ngày 4.
+ **Điểm thi nhiều lần**: Hàng trăm query “tổng điểm từ học sinh i đến j” → build prefix một lần O(n), mỗi query O(1).
+ **Subarray sum = k**: Không chỉ trừ hai prefix; kết hợp **Hash Map** đếm “prefix trước đó đã gặp bao nhiêu lần” để đếm số đoạn con có tổng đúng k.

## 2. Cách hoạt động — từng bước

Cho `arr = [2, 1, 3, 4]`. Build prefix `P` (0-index, **P[0] = 0** sentinel):

| i | arr[i] | P[i+1] = P[i] + arr[i] |
|---|--------|-------------------------|
| - | - | P[0] = 0 |
| 0 | 2 | P[1] = 2 |
| 1 | 1 | P[2] = 3 |
| 2 | 3 | P[3] = 6 |
| 3 | 4 | P[4] = 10 |

**Query tổng index l..r (inclusive):** `sum(l, r) = P[r+1] - P[l]`

Ví dụ l=1, r=2 (phần tử 1+3=4): `P[3] - P[1] = 6 - 2 = 4`.

**Trace Subarray Sum = K (ý tưởng):** Duyệt từng `i`, prefix `s`. Số đoạn kết thúc tại `i` có tổng k = số lần đã thấy prefix `s - k` trước đó (lưu trong map).

## 3. Tại sao giải thuật này đúng?

**Invariant:** `P[i]` = tổng `arr[0] + ... + arr[i-1]` (với P[0]=0).

Tổng `arr[l] + ... + arr[r]` = (tổng đến r) − (tổng đến l−1) = `P[r+1] - P[l]`.

**Subarray sum k:** Đoạn `(j+1..i)` có tổng k ⇔ `prefix[i] - prefix[j] = k` ⇔ `prefix[j] = prefix[i] - k`. Đếm số `j` hợp lệ đã lưu khi duyệt đến `i`.

## 4. Phân tích độ phức tạp

+ **Build prefix:** O(n) — một pass cộng dồn.
+ **Mỗi range query:** O(1) — hai phép đọc mảng P.
+ **q queries không prefix:** O(n × q) — mỗi query cộng O(n) đoạn.
+ **Với prefix:** O(n + q) — amortize chi phí build.
+ **Subarray sum k + map:** O(n) time, O(n) space worst (map lưu prefix).

Dùng `int64`/`long` nếu tổng có thể overflow 32-bit.

## Common Mistakes: 1D Prefix Sum

- **Quên P[0] = 0**: Không có sentinel → công thức sai khi l=0.
- **Off-by-one**: `sum(l..r) = P[r+1] - P[l]`, không phải `P[r] - P[l-1]` (dễ lệch khi l=0).
- **#560 khởi tạo map**: Cần `freq[0] = 1` (prefix rỗng) hoặc logic tương đương — bỏ sót subarray bắt đầu từ index 0.
- **Cập nhật map trước/sau count**: Đếm `s-k` **trước** khi thêm `s` vào map tại cùng index (tránh đếm đoạn độ dài 0 nếu không cho phép).
- **Overflow**: Tích lũy và k lớn → dùng kiểu 64-bit.
