Chào các bạn, binary search không chỉ tìm “có hay không” — nhiều bài cần **vị trí biên**: chèn vào đâu, lần đầu / lần cuối xuất hiện, hoặc giá trị nhỏ nhất làm điều kiện đúng. Đó là **binary search on range** (lower / upper bound).

## 1. Intuition

Trong lớp 30 học sinh xếp theo chiều cao, bạn muốn **chỗ đứng đầu tiên** mà vẫn “nhìn thấy” người cao hơn 170 cm — không cần tìm đúng một người, mà tìm **ranh giới** giữa “chưa đủ” và “đủ”.

Trên array sort: **lower bound** = index nhỏ nhất sao cho `arr[i] >= target`.

## 2. Cách hoạt động — từng bước

**Lower bound (first index với arr[i] >= target):**

```python
lo, hi = 0, len(arr)  # hi = n (past end)
while lo < hi:
    mid = lo + (hi - lo) // 2
    if arr[mid] >= target:
        hi = mid      # mid có thể là đáp án
    else:
        lo = mid + 1
return lo  # insert position hoặc first >= target
```

**Upper bound:** Điều kiện `arr[mid] > target`, còn lại tương tự.

**Trace:** `arr = [5,7,7,8,8,10]`, `target = 7` → lower = 1, upper = 3 → count = 3−1 = 2 lần.

## 3. Tại sao giải thuật này đúng?

Ta luôn thu hẹp sao cho đáp án nằm trong `[lo, hi)` và `hi - lo` giảm. Với lower bound, mọi index `< lo` đều `< target`; mọi index `>= hi` đều không xét — khi `lo == hi`, đó là **first** vị trí thỏa `>=`.

**First + last:** Lower bound cho first; upper bound cho “vị trí sau last” → last = upper − 1.

## 4. Phân tích độ phức tạp

+ **Time O(log n)** mỗi bound
+ **Space O(1)**

Hai lần binary search (first & last) vẫn O(log n).

## Common Mistakes: Binary Search on Range

- **Duplicate:** BS chuẩn trả về *một* index bất kỳ — cần lower/upper cho first/last.
- **hi = n thay vì n-1:** Template `[lo, hi)` dùng `hi = len(nums)` cho insert position.
- **Target ngoài range:** Lớn hơn max → lower bound = n.
- **Binary search on answer:** Không search index mà search giá trị — cần hàm `feasible(x)` monotonic.
