Chào các bạn, từ điển xếp A→Z — muốn tra “Mango” bạn không lật từ trang 1; bạn mở giữa, so sánh, bỏ nửa không cần. **Binary Search** trên array đã sort làm đúng như vậy: mỗi bước loại **một nửa** không gian tìm kiếm.

## 1. Intuition

**Điều kiện:** Dữ liệu **sorted** (hoặc có tính **monotonic** — “càng tăng thì càng đúng”).

**Ý tưởng:** So `target` với phần tử giữa `mid`:

+ Bằng → tìm thấy
+ Nhỏ hơn phần giữa → target nằm bên trái
+ Lớn hơn → nằm bên phải

Giống đoán số 1–100: mỗi lần hỏi giữa, loại nửa.

## 2. Cách hoạt động — từng bước

```python
lo, hi = 0, len(arr) - 1
while lo <= hi:
    mid = lo + (hi - lo) // 2
    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        lo = mid + 1
    else:
        hi = mid - 1
return -1
```

**Trace:** `arr = [1,3,5,7,9]`, `target = 7`

| lo | hi | mid | arr[mid] | Hành động |
|----|----|-----|----------|-----------|
| 0 | 4 | 2 | 5 | 5 < 7 → lo=3 |
| 3 | 4 | 3 | 7 | **found** |

> **Lưu ý:** Dùng `mid = lo + (hi - lo) // 2` tránh overflow khi số rất lớn (C++/Java).

## 3. Tại sao giải thuật này đúng?

Sau mỗi bước, nếu `target` tồn tại thì nằm trong `[lo, hi]` (vì array sort và ta loại đúng nửa không chứa target). Không gian thu hẹp ít nhất một phần tử → tối đa O(log n) bước.

**Invariant:** `target` (nếu có) luôn trong đoạn `[lo, hi]`.

## 4. Phân tích độ phức tạp

+ **Time O(log n):** Mỗi bước chia đôi
+ **Space O(1)** iterative; O(log n) nếu đệ quy (call stack)

## Common Mistakes: Binary Search

- **Vòng lặp vô hạn:** Phải `lo = mid + 1` hoặc `hi = mid - 1`, điều kiện `while lo <= hi`.
- **Array chưa sort:** Binary search sai hoàn toàn — sort trước hoặc đổi approach.
- **Nhầm với lower bound:** Tìm “vị trí chèn” / first/last → dùng template range (bài 17).
- **Mid overflow:** Trên ngôn ngữ 32-bit cũ, dùng `lo + (hi-lo)//2`.
