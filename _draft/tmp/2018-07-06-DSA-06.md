Chào các bạn, ở bài trước ta biết Hash Map tra cứu nhanh như sổ từ điển. Nhưng nếu hai từ khác nhau cùng "trỏ" vào một trang — chuyện gì xảy ra? Hôm nay ta học **collision** (va chạm hash) và các **pattern** dùng hash trong bài thực tế.

## 1. Intuition

Trong lớp có hai bạn tên "Minh". Sổ điểm ghi "Minh" một dòng không đủ — cần **danh sách con** dưới mỗi tên. Hash table làm tương tự khi hai key khác nhau có cùng hash index.

## 2. Collision — cách xử lý

Hai key khác nhau → cùng bucket index → **collision**.

**Chaining (xích):** Mỗi bucket là linked list chứa các entry trùng index.

**Open Addressing:** Tìm slot trống tiếp theo trong cùng array (linear probing).

{% include dsa06-hash-collision-demo.html %}

**Trace through chaining:**
1. hash("cat") = 0 → bucket 0 = ["cat"]
2. hash("dog") = 0 → collision → bucket 0 = ["cat" → "dog"]
3. get("dog"): hash → bucket 0 → duyệt chain → tìm "dog"

## 3. Load Factor & Rehashing

**Load factor** = số entry / số bucket.

Khi load factor > 0.75 (thường):
1. Tạo bảng mới gấp đôi size
2. Re-insert tất cả entries
3. Chains ngắn lại → lookup vẫn O(1) average

## 4. Tại sao Group Anagrams dùng hash?

**Bài toán:** Nhóm các từ là anagram của nhau. "eat", "tea", "ate" cùng nhóm.

**Key insight:** Anagram có cùng **bộ chữ cái** → dùng sorted string hoặc tuple đếm ký tự làm key.

**Invariant:** Mọi anagram map cùng key → cùng bucket trong Hash Map.

## 5. Hash Usage Patterns

| Pattern | Ví dụ | Key trong map |
|---------|-------|---------------|
| Frequency count | Đếm ký tự | char → count |
| Complement lookup | Two Sum | value → index |
| Grouping | Group Anagrams | sorted(s) |
| Visited set | BFS/DFS | node → true |

## Common Mistakes: Hash Implementation

- **Không xử lý collision**: Custom hash table phải có chaining hoặc probing.
- **Bad hash function**: Keys cùng pattern → nhiều collision.
- **Quên rehash**: Load factor cao → O(n) lookup.
- **Dùng hash khi cần thứ tự**: Hash Map không giữ sorted order.
