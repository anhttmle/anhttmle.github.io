Trong phòng thi, giám khảo chọn một bàn làm **mốc** (pivot): ai nhẹ hơn sang trái, nặng hơn sang phải. Sau đó chỉ cần sắp xếp **hai nửa** phòng — không trộn toàn bộ mỗi lần như merge. Đó là Quick Sort — sort **in-place**, nhanh trung bình. Bucket Sort khác hẳn: xếp điểm vào **ống** 0–10, 11–20… rồi gom lại — khi biết trước range nhỏ.

## 1. Intuition

+ **Quick Sort**: Pivot chia không gian; partition một pass O(n); đệ quy hai bên. Giống “chia theo ngưỡng” thay vì merge hai dãy.
+ **Bucket Sort**: Phân phối đều vào bucket theo giá trị/range; sort từng bucket nhỏ (insertion/counting).
+ **K k phần tử lớn nhất (#215)**: Không cần sort cả mảng — **Quickselect** (partition giống quick) tìm thứ k trong O(n) trung bình.

## 2. Cách hoạt động — từng bước

**Partition** (Lomuto ví dụ) `arr = [3, 6, 8, 10, 1, 2, 1]`, pivot = 1 (phần tử cuối):

+ `i` = ranh giới “≤ pivot”; `j` quét; nếu `arr[j] <= pivot` thì swap vào vùng nhỏ
+ Đặt pivot vào giữa hai vùng → pivot index `p`
+ Đệ quy `arr[lo..p-1]` và `arr[p+1..hi]`

**Trace tóm tắt:** Sau partition, mọi phần tử trái ≤ pivot ≤ phải → pivot đúng vị trí cuối cùng.

**Bucket Sort** điểm 0–100, 10 bucket: phần tử 37 → bucket 3; sort từng bucket; nối bucket 0→9.

## 3. Tại sao giải thuật này đúng?

**Partition invariant:** Sau một pass, ∃ index `p` sao mọi phần tử trái ≤ `arr[p]` ≤ mọi phần tử phải. Pivot không cần sort thêm — đã ở vị trí sorted toàn cục.

**Đệ quy:** Sort trái và phải (các phần nhỏ hơn/lớn hơn pivot) → toàn mảng sorted.

**Quickselect:** Chỉ đệ quy một phía chứa thứ k — giống binary search trên không gian partition.

**Bucket:** Nếu phân phối đều, mỗi bucket O(n/k) phần tử, sort bucket nhỏ → tổng O(n) khi k hữu hạn và bucket sort O(1) average.

## 4. Phân tích độ phức tạp

| | Quick Sort | Bucket Sort |
|---|------------|-------------|
| Average time | O(n log n) — pivot chia gần đôi | O(n + k) — k bucket, n phần tử |
| Worst time | O(n²) — pivot min/max mỗi lần (sorted + pivot đầu) | O(n²) — mọi phần tử một bucket |
| Space | O(log n) stack đệ quy | O(n + k) buckets |
| Stable | Không (swap xa) | Có thể (nếu bucket stable) |

**Tại sao average O(n log n)?** Pivot “tốt” chia ~n/2 mỗi bên → cây log n tầng, mỗi tầng O(n) partition.

**Worst O(n²):** Pivot luôn cực đoan → một nhánh size n-1.

Python `sorted()` = Timsort; C++ `sort` ≈ introsort — biết để không nhầm bài implement từ đầu.

## Common Mistakes: Quick & Bucket Sort

- **Pivot xấu trên mảng sorted**: Dùng random pivot hoặc median-of-three — tránh O(n²) cổ điển.
- **Partition off-by-one**: Nhầm Lomuto vs Hoare — thống nhất một variant trong code.
- **Quickselect index**: “Kth largest” = index `n - k` sau partition ascending (hoặc đổi comparator).
- **Bucket Sort general input**: Chỉ hiệu quả khi range nhỏ / phân phối đều — không thay merge/quick cho arbitrary integers.
- **Stable requirement**: Quick không stable — cần merge khi bài yêu cầu giữ thứ tự bằng nhau.
